# session-synapse

给 [pi](https://github.com/earendil-works/pi) 的会话地图：把散落在 `~/.pi/agent/sessions/` 里的会话、追问和分支，组织成一张可拖拽、可缩放的画布。

pi-web 让你看清一个会话，session-synapse 让你看清所有会话之间的关系。

它也以插件形式跑在 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（dsh）里：同一张画布、同一份代码，顶部切换条里叫「会话地图」。

## 它做什么

| 能力 | 说明 |
|---|---|
| 会话地图 | 每次提问 = 一张卡片；同一工作目录的会话归为一个工作区；**默认只画最近 7 天活跃的会话**（在设置里可改） |
| 真实分支 | 按 pi 的 `/tree` 分支与 `/fork` 跨文件分支连线，不另造历史 |
| 工具折叠 | 工具调用与结果按 `callId` 折进对应的助手回答，不单独占卡片 |
| 只读投影 | pi 的 JSONL 是唯一事实来源；画布只做投影与排版 |
| 布局持久化 | 拖拽位置与折叠状态存在 `<agent>/synapse/workspaces.json`，删掉不丢对话 |
| 画布内追问 | 直接在卡片上继续对话，消息发往真实会话 |
| 上下文占用 | 卡片右上角一个圆环，弧长 = 该会话已用的上下文比例；悬停看 `62k / 200k` |
| `/btw` 侧问 | 在卡片上开一个继承当前上下文、工具自选的侧问，收成卡片下的小挂件 |
| 改名 / 归档 | 改名写入 pi 的会话文件；归档走 pi-web 自己的归档 |
| 画布设置 | 右下角齿轮：卡片大小、卡片字体、卡片间距、一个会话默认显示多少天内的卡片（存在本机，对每个工作区生效） |
| 会话详情 | 点卡片进画布自己的详情视图：完整对话（默认最近 50 条，可往上加载）、继续追问、建分支。markdown 按会话里真实出现的构造渲染，**mermaid 图与 LaTeX 公式都是真的**（离线可用，按需加载） |

## 安装

```bash
npm install -g @wjunhere/session-synapse   # 之后直接 `synapse start`
```

从源码跑（开发）：

```bash
git clone https://github.com/wjunhere/session-synapse
cd session-synapse
npm install          # 无运行时依赖，只为跑测试
npm link             # 可选：把它装成一个命令
node bin/synapse.js start
```

启动后打开 `http://127.0.0.1:30142/`。若 pi-web 已在运行，它会被反代到这个端口，顶部中间会出现「对话 / 会话地图」切换条。

### 前提

- Node.js ≥ 22.19.0
- **pi-web 必须已在运行**（默认 `127.0.0.1:30100`）。未启动会看到上游连接错误；用 `--spawn` 可让 synapse 顺带把它拉起来。

### 在 DeepSeek Harness（dsh）里用

画布以**宿主插件**的形式挂进 harness：同一个进程，直接读它的会话服务，不另外起服务、不反代。

```bash
dsh plugin add @wjunhere/session-synapse   # 从 npm 装进当前 profile
dsh web                                   # 启动后顶部出现「对话 / 会话地图」
```

本地改代码时用路径安装：`dsh plugin add link:/绝对路径/到/session-synapse`。

桌面版（Electron 应用）**不要手改 profile**：那个 profile 由应用独占，`dsh plugin --profile desktop` 会被拒绝。在应用里用「设置 → 插件」安装，填仓库的**绝对路径**即可（插件管理器接受 registry 名、git、绝对路径/`link:` 三种写法）。装完重启应用。

| 在 dsh 里 | 行为 |
|---|---|
| 会话地图 / 卡片 / 工具折叠 / 布局持久化 / 设置 | 与 pi-web 下一样 |
| 入口 | 宿主自己那排标签（对话 / 轨迹 / 提示词）里多一个**「会话地图」**，点它出画布、点其他标签回去；没打开会话的那一屏（没有标签行）用一个浮动胶囊 |
| 画布显示哪个工作区 | **跟着宿主的会话走**：宿主换到另一个目录的会话，地图就跟着换过去（地图里没有工作区下拉，入口在宿主的侧栏）。没打开会话时保持上一个 |
| 画布自带多少界面 | **不带**：侧栏、顶栏、视图标签都不渲染，颜色与字体跟随 harness；地图工具在右下角浮动簇（含设置齿轮） |
| 上下文圆环 | 用 harness 自己测的占用（不是估算），数字与它自己的转写一致 |
| 画布内发消息 / 分支 / 改名 / 归档 | 走 harness 的会话服务，真写进会话记录（新会话的第一条消息在 harness 自己的输入框里发） |
| 点卡片页脚的「在 DSH 中打开」图标跳会话 | 切到 harness 的对话视图（卡片页脚的按钮全是图标，意思看鼠标悬停提示） |
| 运行中会话的实时文字 | 有（同进程才有；`dsh headless` 在别的进程写的会话只能事后发现） |
| `/btw` 侧问 | 有，但和 pi-web 不同：工具在草稿卡里多选（默认 `read/grep/glob/web_fetch/web_search`），子会话进 harness 自己的只读权限预设，**不自动归档** —— DSH 的归档会让那个会话从此答不了话（详见 `docs/dsh-desktop.md` §5.3） |
| 卡片间呼叫 | **只有这里有**：卡片左下角的听筒按钮，把这张卡片发给另一个正在运行的会话（详见 `docs/dsh-desktop.md` §7） |
| Agent Teams 成员 | **只有这里有**：Lead 卡片下折成一个小药丸（团队人数 + 每人在跑/失败的状态点），点开才展开成一排 teammate chip，再点 chip 看它自己的只读 transcript；名单从 Lead 日志读，重启后仍在（详见 `docs/dsh-desktop.md` §9） |

画布元数据存在 `$DSH_HOME/session-synapse/workspaces.json`，与 pi 那份互不干扰。

### 卡片间呼叫（只有在这个宿主里有）

一张卡片的左下角有一个听筒按钮。点它，可以把**这张卡片**（它的问题、已经有的回答，还可以再写一句附言）发给**另一个正在运行的会话**。

- 对方会**立刻开始处理**这条消息；如果它正在跑，这条消息会插进它当前那一轮。
- 只能发给活着的会话；发出去的署名是某一个会话（界面上会写明是哪一个）。
- 对方的回复**不会自动回来** —— 想让它回，得在消息里请它回。它回过来时，你这边也会多一张「呼叫」卡片：这个功能是双向的。
- pi-web 下没有这个按钮：那边没有这条通道。

## 选项

| 选项 | 说明 | 默认 |
|---|---|---|
| `-p, --port <port>` | 画布代理端口 | `30142` |
| `-u, --upstream <port>` | pi-web 端口 | `30100` |
| `-H, --hostname <host>` | 绑定地址 | `127.0.0.1` |
| `--data <path>` | 画布数据文件 | `<agent>/synapse/workspaces.json` |
| `--no-projection` | 不自动投影会话 | 投影开启 |
| `--no-inject` | 不向 pi-web 页面注入切换条 | 注入开启 |
| `--spawn` | 顺带启动 pi-web | 关闭 |
| `--force` | 接管另一实例持有的锁（仅当它已挂起时用） | 关闭 |

环境变量：`PI_CODING_AGENT_DIR`、`SYNAPSE_PORT`、`SYNAPSE_UPSTREAM`。

## 为什么需要一个代理

pi-web 会拒绝任何跨源的 `/api/*` 请求（`Origin` 必须等于请求自身的 `Host`），所以画布无法在另一个端口上直接调用它的 API。代理让画布与 pi-web 同源，一次解决三件事：跨源限制、会话跳转、页面注入。

画布以 iframe 覆盖层的形式嵌在 pi-web 页面上，顶部有「对话 / 会话地图」切换条 —— 与 pi-web 原生界面并存，不替换它。

## 上下文占用圆环

每张卡片右上角有一个圆环，**弧长就等于该会话已用上下文的百分比**，不必读数字也知道离上限还有多远。悬停显示精确值（如 `62k / 200k token`），超过 70% 变琥珀色，超过 90% 变红色。

它按 pi 自己的算法算：以最近一次助手回复记录的 usage 为锚点，加上之后新增内容的估算，再除以该模型的上下文窗口。因此**未在 pi-web 中打开的会话也有这个数字** —— 这是 pi-web 本身给不出的。

## `/btw` 侧问

卡片上的 `btw` 按钮开一个侧问，草稿卡里可以逐项勾选它能用哪些工具（默认只读那几个）。它做三件事：

1. **继承上下文** —— fork 当前会话，拿到真实历史（不是拼接文本）
2. **限定工具** —— pi-web 下只给 `read` / `grep` / `find` / `ls`；DSH 下默认给 `read` / `grep` / `glob` / `web_fetch` / `web_search`，可以自己加减
3. **不弄脏主列表** —— pi-web 下自动归档（归档视图里完整可见、可继续）；DSH 下**不归档**，因为它的归档会拦住这个会话发言，侧问会变成哑巴

收纳后它在父卡片下方是一个小挂件（`btw 标题 · N 问 · 百分比`），点开就是完整对话并能继续追问。

> 注意：pi 的 fork 只能从会话当前末尾分叉，所以 pi-web 下的侧问继承的是**整个会话到当前为止**的上下文，而不是某一张卡片之前的部分；DSH 下可以按卡片所在的那一轮分叉。

## 使用

1. 在画布左侧选择工作区（按会话的 `cwd` 分组）
2. 拖动、缩放画布；拖动卡片会自动保存位置
3. 点卡片标题看完整会话，点页脚的 ↗ 图标跳到原生对话
4. 页脚的眼睛图标看这一轮的完整记录（工具调用与回答）—— 卡片页脚的按钮全是图标，意思看鼠标悬停提示
5. 选中回答里的文字可直接带入新的追问
6. 右下角齿轮打开设置：卡片大小 / 卡片字体 / 显示天数（改完点一下「整理」可以按新尺寸重排卡片）

## 地图上显示哪些会话

一个目录积累的会话很多，画布默认只画**最近 7 天有活动**的，其余的收起来（天数在画布右下角的设置里改，可以选 1/3/7/14/30 天或「不限」）：

- 侧栏「会话」列表里，被收起的行变淡，末尾标「7 天前」；标题右侧的计数是「显示中 / 全部」。
- 每一行右侧有一个**眼睛按钮**：点一下收起这张会话的卡片，再点一下放回。这个选择写进画布数据文件，重新加载、换浏览器都还生效。
- 手动放回一条老会话后，它不会再因为「超过 7 天」被自动收起。
- 点击一条已收起的行会直接打开它的转写（地图上没它的卡片，无从定位）。

## 数据与边界

- **pi 的 session log 是唯一事实来源**；画布只投影已提交的条目。
- 画布元数据存在 `<agent>/synapse/workspaces.json`，删除它只丢排版，不丢对话。
- 不修改 prompt、模型请求、工具 schema、provider 路由。
- **同一份画布数据同时只能有一个写入者**，由 `<data>.instance` 锁强制（见下）。

## 同时只能跑一个实例

同一份 `workspaces.json` 只能有一个写入者，否则两个实例的整文件重写会互相覆盖。这一点由**实例锁自动阻止**，再启动一个会直接退出：

```
synapse: 已有实例正在使用这份画布数据（PID 27948，端口 30142，启动于 2026-10-12T14:26:18.728Z）
```

锁键在**数据文件**上（`workspaces.json.instance`），不是端口，也不是进程：

| 情形 | 结果 |
|---|---|
| 再启动一个，同端口 | 拒绝 |
| 再启动一个，**换端口** | 也拒绝 |
| 两个实例指向不同 `--data` | 允许（互不干涉） |
| 进程被杀后的残留锁 | 下次启动**自动接管**，不需手动删 |
| 锁确实被挂起进程占着 | 用 `--force` |

为什么锁定在数据文件而不是端口：最危险的情形恰好是「端口绑定失败但进程不退出」—— 这种进程从未服务过任何请求，却会一直重写数据文件。只检查端口会正好漏掉它。

## 开发

```bash
npm install
npm run check                    # 静态类型检查（基线 0 问题）
npm test                          # 178 个单测，不需要启动服务

# 全套端到端回归：需要 pi-web 已在 30100 运行（脚本不替你启停它）
npm run verify                    # 自己起服务、跑完 26 个套件、清理、汇总成一张表
npm run verify -- --skip-browser  # 只跑不需要 Chromium 的套件
npm run verify -- --only branch   # 按脚本名筛选
# 探测用的模型可以换（默认 trae/DeepSeek-V4-Flash，它挂掉时症状是「卡片上没有分支/侧问按钮」）
PROBE_PROVIDER=cc-switch-open-code-go PROBE_MODEL=deepseek-flash npm run verify -- --only btw

# DSH 适配的回归：自己起一个隔离的 harness（临时 DSH_HOME），跑完自动清理
# 前置：dsh 在 PATH 上 + 有可用凭据（它会真的调模型）
npm run verify:dsh
```

`npm run verify` 用**独立的临时数据文件**起服务（不碰你真实的画布数据），在一次性 cwd 里造探测会话，跑完自动清理；失败时会**保留 run 目录**并打印路径，里面有每个套件的完整日志。单独跑某个脚本也可以（它们读 `BASE`，默认 `http://127.0.0.1:30143`；会创建会话的还要传 `PROBE_CWD`，且目录必须先存在）——完整清单见 [AGENTS.md](AGENTS.md) 的「测试」一节。

CI（`.github/workflows/ci.yml`）只跑 `npm run check` 与 `npm test`：浏览器套件需要 Chromium 和 pi-web 上游，留在本地。

完整脚本清单（每个验证覆盖什么）见 [AGENTS.md](AGENTS.md) 的「测试」一节；哪些改动需要先读哪份约定，也在那里。

### 修复起大的数据文件

若 `workspaces.json` 异常大（旧版本有个工具折叠不幂等的 bug，会反复追加重复的工具记录），可以就地修复：

```bash
node scripts/repair-workspaces.mjs ~/.pi/agent/synapse/workspaces.json
```

它按 `callId` 去除 thread 内的重复工具记录，并保留 thread id（否则浏览器里保存的卡片位置会失效）。修复前请先停掉服务并备份。
